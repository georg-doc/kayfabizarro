## Wo werden die Essays morgen abgelegt?

**Empfehlung: eigenes privates GitHub-Repository `georg-doc/philosophy-sparring-inbox`.** Stand heute: *nicht angelegt oder nicht zugänglich* (der GitHub-Connector unterstützt in diesem Chat keine neue Repository-Erstellung; das bisher erwähnte `georg-doc/KFB-Production-Inbox` konnte nicht als zugängliches Repository bestätigt werden).

**Vorgehen, wenn GitHub die bevorzugte Ablage ist:**

1. In GitHub > New repository einen privaten Namen `philosophy-sparring-inbox` erstellen, **Private** auswählen und mit README initialisieren. Nicht das bestehende `kayfabizarro`-Repo auf privat stellen.
2. Dateien über „Add file → Upload files“ in einen eigenen Ordner `incoming/` laden. Formate `.docx`/ `.doc` und optional die zugrunde liegenden PDFs sind als Originale willkommen. Keine Dateikonvertierung vor dem Upload nötig.
3. Nach Möglichkeit die Originaldateinamen und Fassungsdaten beibehalten; nicht ohne Rücksprache anonymisieren oder verändern.
4. Gib einem ausführenden Chat später den privaten Repository-Link und die ausdrückliche Freigabe, **diesen** Inhalt zu lesen. GitHub-Zugriff und Repository-Berechtigung sind vom jeweiligen Chat/Modell abhängig.
5. Vor der Verwendung zur Profilbildung klären: darf der Text nur analysiert, als Referenz gespeichert, zitiert, extern publiziert und/oder für KFB adaptiert werden? Diese Rechte sind **separat** zu erteilen.

## Alternative ohne neue GitHub-Rechte

Ein **privater Google-Drive-Ordner** ist für mehrere Word-Dateien oft die einfachere Eingabe. Word-Originale dort lassen; selektiv nach Google Docs konvertieren, wenn Kommentare, Textsuche, kollaborative Bearbeitung oder Notebook-Verknüpfung benötigt werden. Der eigene Autorentext bleibt in der Originalfassung nachvollziehbar.

Google Notebook kann DOCX, Docs, PDFs und Markdown als Quellen nutzen; Drive-Imports synchronisieren teilweise automatisch. **Fußnoten und Kommentare aus Google-Dateien werden laut Anbieter nicht importiert.** Daher eine philologische Überprüfung nicht allein aus Notebook-Zusammenfassungen behaupten.

## Empfohlenes schrittweises, menschlich freigegebenes Materialmodell

`incoming/` (Originale, privat) → `catalog/` (private Dateiliste mit Datum/Version/Rechten) → `working/` (private Extrakte, Argumentkarten, Zitierstellen) → `approved/` (einzeln vom Autor freigegebene öffentliche Texte oder Dossiers).

In der öffentlichen Sidequest verbleiben lediglich allgemeine Methoden, recherchierte öffentliche Primär-/Sekundärquellen und **bewusst freigegebene** Ergebnisse. Keine automatische Synchronisation von `incoming/` nach `skills/philosophy-sparring/`.

## Kleine begleitende Metadatenliste

Pro Datei, zunächst **privat**: Dateiname, Originalformat, Verfasser, Werk-/Essay-Titel, Fassung/Datum, Sprache, thematischer Schwerpunkt, Zitationsform/Seitenstruktur, Rechte/Freigaben, ggf. verwendete Autoren/Primärquellen. Erst nach Sichtung eine öffentliche, nicht personenbezogene `SOURCE_INDEX`-Referenz erstellen.

## Grenzen der Tools

Ein normaler Chat bei Claude Free oder ChatGPT Free liest weder private GitHub-Repositories noch Drive-Dateien ohne tatsächlichen Zugang und Berechtigung. Ein öffentlicher GitHub-Prompt allein erzeugt auch keine Schreibberechtigung. Die GitHub-Oberfläche ist als Einstieg zuverlässig; später optional Importer, Auth oder privater Sync.
