## 2 · Code-confirmed architecture facts and caveats

| Upstream source & behavior, read at pinned source | Actual fact | KFB relevance |
| --- | --- | --- |
| \`src/global_tiles.js\` + \`src/main.js\` | Local metric origin per teleport, approximate lat/lon meter conversion, Zoom-14 OpenFreeMap vector tiles, 1 km square chunks; 40×40 km logical index \`GRID_DIM=40\`, \`CHUNK_SIZE=1000\`. Uses a coarse horizon mesh/overview plus active detailed neighborhood. | Strong donor for **cached/query-backed OSM district pocket selection** and streaming (but not proof of continuous planet traversal or exact KFB Story/OSM identities). |
| \`src/main.js\` | Desktop active \`LOAD_RADIUS=2\` → 5×5 chunks, touch \`LOAD_RADIUS=1\` → 3×3; \`UNLOAD_RADIUS=3/2\` hysteresis. Teleport destroys loaded mesh groups and resets pending, payload and local origin. | Camera-driven chunk interest + hysteresis; existing WS1/Travel/Race scheduler must decide what actually loads. No second terrain or player owner. |
| \`src/chunk_worker.js\` + \`chunk_builder.js\` | Worker fetches + decodes source data, computes mesh vertex normals/geometric arrays, roads, bridges, vegetation, collision, lanes; transfers \`ArrayBuffer\` typed arrays to main-thread reconstruction; main-thread fallback exists. | **High-value worker pipeline** comparator for Seed-World/WS1; pin transferable payload schema and prove real KFB source shapes/collision, do not import the upstream engine loop. |
| \`src/main.js\` \`_processChunkBuildQueue\` | One completed worker chunk integrated per frame, CPU fallback task stepped with budget (regular invocation uses 5.5ms). Stale teleport generations checked and unwanted chunks discarded. | Practical frame-spike control pattern, benchmark against existing KFB Seed World donor whose independent queue already has budgets. Stale worker network jobs may still run until they complete; investigate cancellation and ownership. |
| \`src/global_tiles.js\` | Per-context decoded MVT cache capped **24 desktop / 12 touch**; comments estimate ~3–4 MB per decoded Z14 tile; in-flight requests separately coalesced. | Concrete bounded decoded-cache design. | \`src/features/map_tiles.js\` | Separate 2D minimap prep/cache with \`MAX_DATA_TILES=260\`, \`MAX_RASTERS=140\`, \`MAX_CONCURRENT=4\`, LRU-like eviction; avoids duplicate shared decode cache where called. | Separate main/worker/minimap caches to reconcile in KFB memory audit; avoid hidden double caches and CORS errors. |
| \`src/features/bridge_profile.js\` | Connected graph with bridge deck clearance and grade propagation; class-specific 5%/7%/10% approach grades, same DEM/source ways across chunk boundaries; static import possible after adapter. | **Especially valuable donor** for KFB Köln Rhein bridges + Track Core support seams.
