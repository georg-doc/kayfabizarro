## Proposed NotebookLM input experiment

Google's source help states that a Web URL is used by scraping **text on one HTML page**. Markdown file uploads are allowed, but that does not imply that an imported file keeps refreshing from future Git commits. The documented Google Drive `Click to sync` behavior is **not proof for GitHub web sources**.

The user should test one GitHub blob page with a precise unique content marker and observe:
- Did the source actually import the expected author text, not GitHub navigation chrome or README snippets?
- Did a subsequent commit to the same stable branch URL change the imported source when refreshed/reopened?
- If not, is removing and re-adding the source necessary? Record that as a manual snapshot limitation.
- Do not use a commit-hash URL for the refresh experiment: an immutable commit URL can never reflect later revisions.
- Do not announce a live URL or public acceptance surface until that exact URL shows the requested head/content.

Keep the old Google Docs sources available as a **temporary operational NotebookLM fallback** until this controlled test passes. No Site/Cloudflare/GitHub Pages substitute, and no auto-merge/promote Live.
