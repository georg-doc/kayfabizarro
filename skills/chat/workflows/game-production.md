# Workflow · Game Production

1. Open the project SSOT and current return.
2. Verify current main/branch/PR.
3. Read relevant contracts and only the donor/tool nodes needed for the slice.
4. Classify planned dependencies: REUSE UNCHANGED / ADAPT / DEFER / REJECT.
5. Confirm owner boundaries.
6. Implement one coherent playable slice.
7. Run static/numerical/regression tests.
8. Run real browser QA when the slice has browser-visible/runtime behavior.
9. Publish a separate WIP/preview when human freeplay or visual acceptance needs it.
10. Request Georg visual/freeplay feedback when look, feel, timing, readability, play experience or the project SSOT makes human acceptance a gate.
11. Update return and additive changelog.
12. Merge authority always comes from the project contract. Human freeplay is a merge gate only when the slice/project contract requires it; otherwise an authorized Astra/WSA routine merge may proceed after the project-specific review/test gates are satisfied.

Never turn this generic workflow into a stricter or looser merge policy than the current project SSOT.
