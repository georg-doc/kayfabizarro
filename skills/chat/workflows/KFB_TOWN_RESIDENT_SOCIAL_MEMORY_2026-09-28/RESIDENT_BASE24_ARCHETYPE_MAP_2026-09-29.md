## 1 · Why Base-24 is a curation problem

The current Resident Atlas session cut contains **27 resident recipes**, but recipe count is not Resident count:

- `Farmers` contains Farmer_A + Farmer_B;
- `The Protagonists` contains Protagonist_A + Protagonist_B;
- `Orc Warband` is an ensemble;
- Animatronic represents two states of the same character;
- Graveyard/Disco work adds the Skeleton Minion beyond the old three-Skeleton Atlas trio.

Town also has important social characters that are not simply Atlas recipes:
- King Kayfabian / Paladin;
- Offica / Officer Doppeldenk;
- Vampire as a current separate-home direction;
- FrizzleBob as Herald / Guide.

Therefore **Base-24 means 24 authored social identities**, not the first 24 source models.

## 3 · Selection heuristic

A Base-24 Resident earns a slot when they add several of these at once:

1. distinct social friction;
2. distinct habitat / residence / biome;
3. distinct activity loop;
4. distinct Jung/Journey function;
5. useful Signature Deck angle;
6. recognizable Gift / Brick Fish / dance / Card response;
7. source-backed actor or clearly identified source gap;
8. useful relationship pressure against several other Residents.

The goal is a conflict-rich ensemble, not archetype bingo.

## 7 · Personality-mix shortcut

For fast testable character authoring, a Resident can begin with a **three-vector blend** rather than a long biography.

Use:

```text
social mask
+ cognitive style
+ comic failure mode
```

Examples:

```text
Lorekeeper
quiet archivist
+ evidence-first pattern keeper
+ mistakes documentation for understanding

Black Knight
formal professional
+ boundary / honor thinker
+ escalates tiny etiquette breaches into ceremonial challenges

Protagonist A
curious peer
+ high-signal social scanner
+ confuses novelty with importance
```

These are influence vectors, not impersonations. Later Lean Memory and authored history should make the Resident more specific than the seed.

## 9 · Dialogue / thought presentation direction

The requested visual direction is compatible with the existing ChatterBox attention budget **without creating a second dialogue engine**.

### Speech
- clean designed rectangular box;
- lightly rounded corners;
- high readability over 3D scenes;
- not Claymation;
- not Cavey/KFB-outline treatment;
- existing speaker-tail / anchor semantics may be reused under a new presentation skin;
- one active NPC speech box is normal;
- two simultaneous speech boxes remain the soft maximum.

### Thought
Use a visually related but clearly distinct thought treatment for:
- private contradiction;
- micro-reaction;
- remembered grievance;
- unsaid retort;
- current preoccupation.

Thoughts should be short enough that they do not become a second narration channel.

A useful rule:
**speech changes the social scene; thought changes how the player reads the Resident.**

Do not let every interaction generate both.

## 10 · Resident Interaction MVP direction

A useful first playable Resident-world MVP can be:

```text
Resident routine
→ POI Attention
→ Curiosity / Interest
→ Expectation
→ interaction
→ one speech / choice beat
→ optional Card handoff
→ visible Reaction Choreography
→ optional short thought beat
→ conditional Lean Memory receipt
→ resume / retarget routine
```

Minimum proof should include:
- two contrasting Residents;
- one real activity each;
- one interrupt + clean resume;
- one Gift or Card handoff;
- one context-sensitive reaction;
- one speech-box interaction;
- one thought-box reaction;
- one meaningful memory receipt;
- later revisit that demonstrably changes one response.

This is the smallest loop that tests **character + activity + dialogue + memory + embodied reaction** together.
