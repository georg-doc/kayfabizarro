# CLAUDE DESIGN VISUAL GATE · Hex Project Islands

## Why use the fresh Claude quota here

Claude Design is useful for **spatial composition and art direction**, not for reconstructing working KFB runtime logic.

The previous failure pattern was:
- real donor loaded;
- source behavior abstracted/reinterpreted;
- plausible replacement built;
- visual/functional parity silently lost.

This slice avoids that.

## Visual question

Design a convincing KFB **Project-Island world language** around the already-working three-hex base.

Show exactly three candidate views of the same source-based composition:

- overview / map read;
- player traversal read;
- vertical/elevation read.

The composition should communicate:

- Level 0 = safe three-hex start;
- quick-win project one friendly jump away;
- project categories/statuses readable by color;
- lower archive/Graveyard band;
- one upper future-project band;
- Card Zone / Sky Card identity survives;
- world feels like a place, not a dashboard.

## Hard constraints

Do not:
- rewrite Card Zone v2;
- create a new card implementation;
- create generic replacement hexes;
- create a new movement controller;
- generate a random island layout;

- invent a Resident;

Every placed object answers:

**Why is it here?**

For the visual gate:
- project hex position = progression/readability reason;
- prop = project/resident narrative reason;
- bridge/jump line = traversal reason;
- vertical band = project status/history reason.

No decorative scatter without relation.

## Color
