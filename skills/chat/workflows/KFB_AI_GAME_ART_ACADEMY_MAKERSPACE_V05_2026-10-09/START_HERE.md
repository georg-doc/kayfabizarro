## 2. Product SSOT · Maker Space island

### 2.1 World role

The Academy is not a separate universe and does not need a second world engine. It is a **Maker Space island / workshop district** using the same KFB World grammar as other islands.

Its special identity comes from activities and presentation:
- surreal 3D printers producing changing objects;
- workbenches / rigs / material specimens;
- small shader and animation test objects;
- Resident makers working visibly;
- a performance/display stage for finished models, rigs, animations or experiments;
- the existing Card/Deck and HyperNormalisation layers recontextualized for making, craft, curiosity and creative dissent.

The island may later use creativity/inspiration quote subsets, but quote truth/provenance stays with the existing Quote/HyperNormalisation owner.

### 2.2 Primary spatial interface

**Large Clay MediaSurface / amphitheatre stage** is the default learning surface.

Expected states:
1. **World view:** the player approaches the stage while the KFB world remains fully visible.
2. **Engaged view:** camera frames the screen/stage and keeps enough island context to feel diegetic.
3. **Immersive lesson view:** lesson expands close to fullscreen, but the KFB world remains perceptible at the edges/background and the clay/cartoon HUD remains visually coherent.
4. **Return:** one gesture returns to the same physical position/state in the Maker Space.

Do not create a generic web dashboard around this. The Academy's browser controls should feel like the current KFB clay/cartoon world UI and Racer HUD family, while remaining readable.

### 2.3 Portal / door / instance

A door or portal may enter a focused lesson/classroom instance **only through the existing World portal/instance/threshold owner**. It must not become a parallel navigation/runtime system.

Useful interpretation:
- ordinary state: workshop door behaves as local physical architecture;
- Academy/unlocked state: same threshold may transition to a focused classroom/workshop instance;
- return restores the Maker Space context.

The focused instance may visually borrow the spatial tutor logic of the 3D AI Classroom donor, but should use current KFB character/rig/material sources.

### 2.4 Tutor

The future AI tutor is not a floating generic chatbot.

Tutor responsibilities:
- explain a visible object or tool;
- ask short diagnostic questions;
- inspect the current task context when a connector/tool contract permits it;
- suggest one next manipulation;
- request a Feynman explanation or recap;
- compare the learner's result to explicit lesson criteria;
- help debug Blender/Three.js/engine tasks without pretending to have observed tools it cannot actually inspect.

The tutor can be represented by a current KFB character/Resident after source isolation. Historical Cube Pet / FrizzleBob presentation is a donor, not automatic character canon for the new Academy.

### 2.5 Curriculum scope

Initial Academy scope is 3D/Game Art, project-first:
- 3D fundamentals and spatial reasoning;
- modeling / topology;
- UVs, materials, textures and stylized surface language;
- lighting / cameras;
- rigging / skinning / animation;
- Three.js / WebGL / WebGPU foundations;
- Blender workflow and export;
- game-engine transfer concepts (Godot / Unity where useful);
- optimization, draw calls, geometry, texture cost;
- KFB-specific asset provenance, kitbashing/frankensteining and source-isolation practice.

The historic 30 three.js lessons become **seed content**, not the whole curriculum.

The curriculum should be benchmarkable against professional Game Art / 3D Animation learning outcomes, but should remain individualized and project-first rather than imitating a school timetable.

### 2.6 Personal learning loop

A lesson should usually produce a visible object, change or artifact:

1. **Recapture:** short recall from prior work.
2. **Demo:** one source-proven object / technique.
3. **Manipulation:** learner changes it.
4. **Explain:** learner describes why the change works.
5. **Build:** apply to a KFB or personal project object.
6. **Show:** stage/render/compare the result.
7. **Recap:** compact note / retrieval prompt for later spaced repetition.

No mandatory points/XP layer is required.

### 2.7 Maker-stage outputs

The same stage can display:
- three.js live lesson;
- shader/material comparison;
- GLB/model turntable;
- rig/animation loop;
- procedural geometry;
- Blender render/video;
- Card/deck lesson;
- PDF/reference;
- HTML tool;
- later engine capture or remote tool session where technically supported.

This is a **presentation contract**, not permission to embed arbitrary privileged code in the World runtime.
