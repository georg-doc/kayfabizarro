# Workflow · Tool Production

1. Identify the tool owner and current source tree.
2. Preserve working modules and measured contracts.
3. Add a small tool node, not a duplicate knowledge base.
4. Publish human UI plus machine-readable docs from the same source revision.
5. Required machine-facing minimum: START/SSOT/CONTRACTS or equivalent, module index, known issues, changelog, LLM manifest.
6. Mark legacy predecessors explicitly rather than deleting them.
7. Test the actual published tool, not only the standalone/local source.
8. Add the current tool to `skills/chat/REGISTRY.json` only after its implementation SSOT/site is pinned.
