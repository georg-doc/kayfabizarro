## Product intent

Every real 3D authoring/review surface should be able to show the same current KFB world presentation instead of inventing its own gray lab, light rig, ground plate or palette.

First consumers:

1. Resident Atlas;
2. ToolBox / Animation Studio.

Later consumers may include Vehicle Studio, NPC scenes, Billboard/Media previews, Combat/Stage recipes and other real 3D review hosts.

This is **not** a new WorldBuilder, terrain engine, sky owner or renderer.

## Required preview modes

### 1. WORLD_MATCH · default

Use the current KFB world presentation through delegated providers:

- sky / atmosphere;
- light rig;
- fog;
- tone mapping / exposure;
- palette / world mood;
- shadow/contact profile;
- ground/material family;
- optional support/terrain patch.

This should be the default for normal Resident Atlas / ToolBox previews.

### 2. SOURCE_ISOLATION

Neutral source-proof environment for checking the actual donor without beautification.

Requirements:

- neutral background;
- neutral, readable light;
- simple source support plane only when needed for scale/contact;
- no mood grading that can hide source defects;
- clearly marked as source isolation.

### 3. CONSUMER_PRESET

A named profile sourced from an actual environment owner, for example:

- `world.current`;
- `world.evening`;
- `world.night`;
- later `combat.spindle`;
- later a named authored World/OSM zone.

A consumer preset is a profile/reference, not a forked environment engine.

## Support levels

Do not force every preview to load a whole world.

```
ground
terrainPatch
worldZone
```

- `ground`: current ground/material/contact-shadow grammar only;
- `terrainPatch`: small real current terrain/support sample;
- `worldZone`: actual authored WorldBuilder/OSM zone when the task needs spatial context.

The host owns support queries. Resident/ToolBox modules do not create hidden baseplates to compensate for uneven ground.

## Candidate contract

Prepare the smallest useful candidate such as:

`kfb.environment-preview/0.1-candidate`

Suggested semantics:

```js
const env = mountEnvironmentPreview({
  THREE,
  host: { scene, camera, renderer },
  mode: 'WORLD_MATCH',
  preset: 'world.current',
  support: 'terrainPatch'
});

env.applyPreset('world.evening');
env.update(dt, hostFacts);
env.probe();
env.resolveProfile();
env.dispose();
```

The exact API may differ after source inspection, but these owner boundaries are binding:

### Host retains

- renderer;
- scene;
- camera;
- clock;
- resize;
- gameplay/movement;
- editing state;
- persistence;
- world collision.

### Environment provider retains

- sky/atmosphere recipe;
- light/fog/palette facts;
- terrain/support facts when a real patch/zone is requested;
- current profile/source revision.

### Preview adapter owns only

- selecting a provider/profile;
- mounting/unmounting provider-owned presentation objects into the host;
- translating the host's generic preview request to provider calls;
- reporting the exact resolved profile/source revision.

## Current vs pinned

Daily authoring may request:

`preset: "world.current"`

But saved evidence/config must resolve and record the exact source/profile revision used.

A review artifact should therefore be able to report something like:

```json
{
  "requestedPreset": "world.current",
  "resolvedProvider": "travel-world-presentation",
  "resolvedRepo": "georg-doc/KFB-Travel-Globe",
  "resolvedHead": "8614282aab2ced43bb5dda9fcf7abadf9768100a",
  "support": "terrainPatch"
}
```

Do not use an unrecorded moving `raw/main` dependency as acceptance evidence.

## First two consumer proofs

### A · Resident Atlas

Use one current real Resident scene/module.

Prove:

- SOURCE_ISOLATION;
- WORLD_MATCH;
- same Resident source and transforms in both;
- no mandatory baseplate;
- support/contact still correct;
- environment dispose/reload does not mutate Resident ownership.

### B · ToolBox / Animation Studio

Use one current real actor.

Prove:

- SOURCE_ISOLATION;
- WORLD_MATCH;
- animation/mixer remains ToolBox/Animation-owned;
- environment changes do not change motion/pose truth;
- support/contact shadow is readable;
- switching environment does not create a second scene/renderer.

## Visual controls

Normal production UI should expose only a compact environment selector when useful:

- World Match;
- Source Isolation;
- named Consumer Preset.

Detailed sky/light/fog diagnostic controls may exist behind debug/authoring state, not as permanent review chrome.

## Explicit non-goals

Do not:

- rebuild Travel;
- copy Travel sky/terrain code into every consumer;
- add another terrain generator;
- add another scene/camera/renderer;
- make a generic environment editor in this slice;
- make every historical sky selectable;
- add weather/day-night systems not already source-backed;
- normalize Combat Spindle into Travel;
- make Resident modules own terrain;
- introduce generic gray plates as the new default.

## Done when

1. Resident Atlas source in SOURCE_ISOLATION and WORLD_MATCH;

4. no duplicate renderer/camera/terrain/animation owner;
5. mount → switch → update → dispose → remount works cleanly;
6. no hidden baseplate is introduced;
7. saved/review evidence records the resolved environment revision.
