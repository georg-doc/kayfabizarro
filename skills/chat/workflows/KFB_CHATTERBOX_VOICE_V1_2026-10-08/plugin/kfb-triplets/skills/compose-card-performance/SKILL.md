# KFB Triplets · source-first Web-Chat authoring v0.1

## Identity: authoring workflow, not another runtime
This plugin is a **skills-only chat composer**, modeled on the workflow pattern of **KFB Asset Scene Composer**. It does not itself host a Site, create a replacement Card/Triplet database, add a ChatterBox semantic engine, synthesize voice, call Suno, authenticate to GitHub, or control the KFB Audio player. Use already connected GitHub and KFB Production Control tools separately when available and authorized. The existing audio site handles listening. The plugin's reusable outputs are editable content and provenance.

**Fixed owners:** Original cards in `georg-doc/kayfabizarro/media/kfb/` plus `media/kfb/index.json`/current Registry, content in the existing ChatterBox Voice Draft PR **#379** on its current branch, audio/mixing/site in existing KFB Audio Draft PR **#365**, existing Site `https://kfb-audio.frizzlebob.chatgpt.site/` → **Voice Acting**. GitHub owner/branch/head can evolve. Re-read current exact branch state; do not freeze the 2026-10-12 commit IDs into future writes. No Site deployment for data-only edits.

Read GitHub `skills/chat/START_HERE.md`, `skills/chat/CHAT_GITHUB_KFB_STAGE_WORKFLOW.md`, `skills/chat/FRESH_CHAT_SLICE_PROTOCOL.md`, Voice `START_HERE.md` and `RETURN.md`, Audio current `RETURN.md`, and any named SSOT/brief; GitHub wins over chat or plugin memory. ## Inputs and scope
Accept exact `deckId` or deck title/JSON path, plus **Card IDs**, a verified four-card source page, whole deck, or deliberate cross-deck combination. Optional persona, Story Mode (`tragic`, `comic`, `absurd`, `heroic`, `mystical`, `forbidden`), voice profile, ordering, target length, Suno style, bed, audience and output format. Default when unspecified: source deck/card truth first; 3 cards in original order; dry/deadpan voice; `EDITORIAL_CANDIDATE`; never auto-publish feed. Ask only for truly missing source identity that cannot be recovered; for material choices prefer reasonable editable defaults.

## Read / isolate the real source
1. Fetch the current GitHub JSON at an explicit ref, record Git blob SHA, validate deck source identity, card IDs, Card titles, raw `power`, raw `lore` (null allowed), `artworkPrompt` and page/card crop registry mapping. Use the exact original Card title (don't quietly improve it). If there is no `lore`, don't invent it.
2. **One spoken Triplet is one short grammatical utterance**, assembled as internal `subject → connector → reframe`; in Card-based use preserve genuine title/POWER/LORE anchors and an effect/consequence. It is **not three stand-alone sentences**. Separately tag the text `EDITORIAL_DERIVED_NOT_VERBATIM`, even when power and lore words are exact source excerpts. One Card may have a valid silence outcome.
3. A **Bridge** between Card utterances is a *different, higher-level semantic object*: describe why the prior concrete state makes the next Card act, obstruct, reframe, retaliate, impose a cost or callback. Use punchy oral syntax, no robotic repeat `therefore/but/and then`. A bridge is authored comedic stage logic, NOT original card game mechanics. Preserve `from/to` source IDs, source revision, relation kind and editable status; don't fill gaps with unrelated invented characters or lore. When no valid causal link exists, explicitly allow cut/silence/scene reset or change Card order.
4. Editor modes: `CARD` 1 line; `THREE_CARD` (three lines + 0–2 compatible Bridges); `FOUR_CARD_PAGE` only with verified page/quadrants; `DECK` all original Card IDs with exactly one Card beat per ID; `CROSS_DECK` with explicit multiple deck refs; `SPEAKERS_CORNER`/`TAVERN_ENSEMBLE` with actor cues, not a new runtime. Show/Spin/Sell/King Quest is the **higher-scale** story grammar, not three speech sentences per Card.
5. Fractal story continuity: name a POV and stake, chain real Card actions via plausible cartoon cause/cost/reversal/callback, vary tragicomic beats and pacing, end coherently. No generic narrator filler, pop-culture imitation-by-quotation, canned AI punchlines, metaphor-heavy explanation, or invented rules. `RULE1`: each spoken line must provide a concrete mechanism, cost, image or dramatic progression.
6. **Card Performance outro (not ordinary functional NPC dialogue): exact final spoken line `Stay Fluffy!`**. Optional character-specific intro `Welcome, dear Fluffheads!`; don't repeat it in every Card or make it mandatory for unrelated game speech. Character variations don't change Card source content.

## Output format and test routes
**Default human-facing response:** Immediately usable **plain English text**, not a JSON dump. For Suno provide separate **Lyrics / Speech** and **Style** in copyable plain text. Spoken Lyrics use minimal `[Spoken Word]`/`[End]` only if needed; `Stay Fluffy!` last audible line. Track actual Unicode codepoints against 5,000 when requested; don't claim song duration from codepoints alone. If one-card-per-beat for a full deck won't fit, split into parts or offer a documented alternative, never drop Cards silently. Full deck Suno = one event/sentence per real Card, tracked ordered `cardNumber` list.

**Existing Audio Site:** Generate a complete **importable local draft JSON** matching exactly `kfb.audio-site.card-performance-draft/1` in the current Audio owner `tools/KFB-ToolBox/audio/card-performance-self-service/card-performance.js`, with `sourceRepo/sourceRef/sourceRevision`, `contentRevision`, `fetchedContentSha`, `deckId`, `selectedCardNumbers`, `lines` keyed by Card number, `bridgeDrafts` keyed `from>to`, speaker, storyMode, seed, intro, bed (`D`/`DRY`), delivery, rate/pitch. Draft status `LOCAL_EDITORIAL_DRAFT`; bridge status `LOCAL_EDITORIAL_CANDIDATE`; no canonical promotion. The Site imports local JSON (or pasted text) from **Voice Acting**; importing a draft does NOT make it part of the automatically loaded feed. Save JSON file plus the readable lyrics/style alongside when asked. Use [outputs-and-safety](references/outputs-and-safety.md).

**GitHub Check-in requested:** Use the existing connected GitHub tool as a separate authorized action. Write additive candidates under current ChatterBox Voice owner branch, not directly into original Card JSON or Audio runtime. Before each GitHub write get exact branch HEAD and target file SHA (if replacing), after the write verify **exact branch HEAD and intended file(s)**. If timeout/UNKNOWN, inspect before retrying. Update owning Voice Return/additive changelog at the meaningful checkpoint; KFB Hub/router only when canonical URL or material P0 routing changes. Never overwrite current active `KFB_AUDIO_SITE_CARD_PERFORMANCE_FEED_R1_2026-10-12.json` or increment its preview revision without explicit permission to change what listeners will see. Keep the current `r3` human listening gate if still open.

**Listening and publishing:** KFB Audio existing Site v9 (or current verified revision) supports `Voice Acting`, `Reload GitHub content`, local `Play dry` / `Play D`, voice/casting controls, JSON/text import and export. A GitHub **content-only** update to the explicit preview feed may be tested with Reload WITHOUT a new Work run/deploy, once permission and schema rules are satisfied; a sidecar/draft on GitHub alone is NOT automatically visible after Reload. Suno uses plain-text copy/paste; this skills-only plugin cannot create or download Suno songs, stems, timelines or captions. Any audio timing must be measured on the exact recorded voice file, never reused from another take.

## Verification and return
Keep reproducible checks: original selected IDs and title match; actual source POWER/LORE anchors for each line; one Card sentence; Bridge concrete hinge; page/deck exhaustiveness and order; fixed ending; correct schema + audio import semantics; actual character count and source blob. Distinguish `SOURCE_VERIFIED`/`EDITORIAL_CANDIDATE`/`HUMAN_ACCEPTED`/`AUDIO_TESTED`/`SITE_VISIBLE`/`LIVE` (only evidence can advance each). A static pass never establishes comedy quality or actual site audio. Finish concise: speaker, Card IDs/page/deck, copy-ready performance, draft/lyrics links or connector refs when actual files exist, GitHub repo/branch/head/changed files/readbacks when written, whether active preview was changed, audible proof status, exactly one next gate. Do not auto-merge, stage, release or promote Live.
