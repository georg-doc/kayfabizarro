# KFB Visual Studio · Interactive Webchat Review Session R1
Date: 2026-11-22 · **PROPOSAL / NOT IMPLEMENTED** · Owner: `georg-doc/kayfabizarro` KFB Visual Studio #479 · Parent Draft PR #480.

## 0 · Outcome and protected owners
User needs a **visual decision board inside normal ChatGPT Webchat**, not a second game runtime or more abstract conversations about style. A pre-recorded, exact-state `kfb.visual-replay/0.1` packet from the real game supplies actual screenshot/video/audio and causally linked metadata. The private KFB Game Art Director plugin presents a scannable session check-in, permits detailed visual discussion/alternative target generation, records explicit Georg decisions, and commits **only the accepted evidence/decision package** to the existing GitHub coordination workflow. Claude Code remains the *sole receiving game implementation writer*, not a writer of the visual critic plugin.

Read-first: [Replay/Quality Contract](./CONTRACT.md), [machine schema](./review.schema.json), [Visual Studio #479](https://github.com/georg-doc/kayfabizarro/issues/479), [scene deep-link #478](https://github.com/georg-doc/kayfabizarro/issues/478), Race receiving owner/Return, existing KFB Game Improvement Lab `skills://plugins/kfb-game-improvement-lab/improve-kfb-game/skill.md` (reuse five perspectives, do NOT silently create duplicate game runtime), `skills/chat/workflows/visual-qa.md`.

## 1 · Real capabilities, not assumed
- **Webchat-native DIL-style interactive responses** can display compact controls and progressively disclosed grounded data. But these are a response UI, **not by themselves an installable persistent plugin UI** nor an authenticated GitHub write.
- For reusable **embedded HTML/JS** in a plugin, use **MCP Apps interactive UI resources**, structured actions and, if suitable, Extensions (`ui/update-model-context`, `ui/message`, deep links, display modes) against a permission-aware backend. The plugin's skill supplies KFB instructions; MCP server tools supply source-backed reviews, media, draft/version actions and GitHub recording. An MCP App view has no default unrestricted browser or code/filesystem access.
- OpenAI MCP Extensions docs: https://github.com/openai/mcp-extensions/blob/main/docs/spec.md and https://github.com/openai/mcp-extensions/blob/main/docs/patterns.md . As documented 2026-11-22: **Web host update-model-context image content is not supported**. Keep photo/video as server-hosted permissioned media resources or user-attached images, with selected text/structured refs passed to the model. **Do not claim embedded browser visuals automatically reach ChatGPT ImageGen.**
- ChatGPT **native image editing** is used conversationally on the actual attached screenshot. Plugin cannot silently invoke ImageGen or automatically capture generated bytes until a concrete round-trip is proven. Audio/SFX redesign is a critique, timing-sheet and target-reference proposal until an actual supported audio generation tool/owner produces original audio.
- **Cost-neutral** means viewing cached evidence and using local client interactions need not launch model/image generation. It does **not** mean unlimited zero-cost ChatGPT messages, expensive plugin backend, cloud storage, video transcoding or ImageGen. Cached UI should not continuously re-run critics. Confirm quotas before claims.
- Desktop-specific WebMCP is not equivalent to universal normal-Webchat support; the intended Webchat delivery is a hosted MCP App view/plugin tested on web and mobile separately.

## 2 · Information architecture — four layered views
**Level 0 / session check-in**: project, current review ID, linked build/head and capture confidence (`ACTUAL_GAME`, `TARGET_GENERATED`), device and capture UTC; 3 most impactful findings + compact counts `P0/P1/P2/P3`, `OPEN`, `PROPOSED`, `APPROVED`, `HANDOFF_COMMITTED`, `RETEST_PENDING`, `VERIFIED`; 1 next decision. Never paint all defect cards at once.

**Level 1 / visual issue card**: original real frame/timecode, 1-sentence defect, impact and **confidence**, target Golden if existing, source/owner, proposed low-effort/high-impact fix, button/link `Compare`, `Discuss`, `Create target variant`, `Mark as no-fix`. For unknown media show `EVIDENCE_MISSING`, no fake thumbnail. Cards sorted by P0 then high impact/low effort, not artificially ranked absolute aesthetics. Show source object in isolation before using required donors.

**Level 2 / detailed comparison**: Before / accepted target / actual-after 2D slider; annotated hotspot bounding regions/timecodes; A/B/C switch for alternative changes, short looped clip or time-striped VFX/audio review; exact frame↔event↔flags↔camera/shader/particle/device payload is collapsed by default; independent critic vs builder review labeled. Fast visually legible controls; reversible `keep original` vs `approve option A/B`, optional written comments. A visually generated target is always labelled `GENERATED_TARGET`, never `ACTUAL_GAME`.

**Level 3 / approval and handoff**: immutable selected versions and media SHA list, itemized decisions, owner/branch/commit target, unapproved findings excluded, risk/regression check and rollback reference. Explicit `Approve selected design decisions` is a Georg act recorded with revision; separate `Commit decision packet` is a permissioned tool call that must only run on a user action, guarded on expected previous version, and return GitHub commit SHA + file readback and new branch HEAD. **Approval is not automatically a GitHub commit; commit is not code implementation; code implementation is not test PASS; acceptance is not auto-merge/Live**.

## 3 · State machine / concurrency
Session:
`CAPTURE_REFERENCED → CHECKIN_OPEN → CRITIQUE_IN_REVIEW → TARGET_VARIANTS_PENDING → DECISION_READY → GEORG_APPROVED → PACKET_COMMITTING → HANDOFF_COMMITTED → CLAUDE_IMPLEMENTING → RETEST_EVIDENCE_READY → INDEPENDENT_CRITIC_REVIEWED → [GEORG_PRODUCT_ACCEPTED | REPAIR_PENDING | QUARANTINED]`.
- Per-finding: `OPEN | REGENERATE_REQUESTED | OPTION_SELECTED | KEEP_ORIGINAL | NO_FIX | APPROVED | COMMITTED | REPAIRING | RETESTED`. One finding can be accepted while other findings remain open; no global incomplete-session blocker unless a genuine P0 prevents the named outcome.
- `REGENERATE_REQUESTED` opens a *new* explicitly linked proposal (`parent_variant_id`, screenshot SHA, target version); never overwrites previous proposal or Golden. New ImageGen variant must be attached/registered with actual hash before selectable as committed artifact.
- Every write uses `session_revision` optimistic guard, idempotency key, `expected_head` for GitHub, UTC, actor/role (Georg vs AI), permission checks and audit event. On changed head/conflict: re-read and surface the difference, never force-push.
- After clicking `Commit`, state stays `PACKET_COMMITTING/UNKNOWN` until read-back; on timeout inspect exact source/issue/commit before retry. Only server response with verified file+HEAD may display `HANDOFF_COMMITTED`.
- Undo is a **new compensating decision revision**; approved Golden bytes and historical events never deleted. Restoring game output requires owner-controlled compatible source/asset/save rollback + new runtime test.
- Approval gating may use named human product-design decisions; automated technical diagnostics do not require Georg to approve each micro-adjustment.

## 4 · Minimal plugin contract / tools
Use the existing KFB GitHub app plus minimal dedicated service for private media and durable session state where necessary. Avoid duplicate GitHub or gameplay owners.
| Tool | Reads/Writes | Responsibility |
| --- | --- | --- |
| `list_review_sessions(project?)` | READ | Names, priority/status, head/role, accessible sessions |
| `get_review_session(session_id)` | READ | Snapshot, top findings, exact GitHub/evidence pins and media reachability |
| `get_finding(finding_id)` | READ | Canonical evidence, before/after, timecode, event chain, current decision revision |
| `get_media(media_id)` | READ | Authorized original image/video/audio bytes or signed permissioned resource |
| `propose_variant(finding_id, type, parent_id, evidence_refs)` | DRAFT WRITE | Record variant request/intent, **not** promise ImageGen/AudioGen execution |
| `register_generated_asset(variant_id, authorized_bytes_or_asset_ref, sha256)` | DRAFT WRITE | Hash + verify produced output from real supported attachment path |
| `set_finding_decision(finding_id, verdict, chosen_variant_id?, expected_revision)` | REVIEW WRITE | `KEEP/APPROVE/REGENERATE/NO_FIX`; only named human explicit approval can set APPROVE |
| `preview_handoff(session_id, selected_ids)` | READ | Complete candidate source, SHA list, target repo/branch, proposed ticket and diff/no-go findings |
| `commit_handoff(session_id, expected_revision, expected_head, idempotency_key)` | GITHUB WRITE | Explicit authenticated user act, optimistic CAS, private-media routing, actual GitHub readback |
| `get_handoff_status(session_id)` | READ | Verified commit/PR/head and later actual test/critic status |
OAuth/identity: validate viewer/actor and repo/media access server-side; public GitHub issues contain redacted metadata only when private art/media is involved. Auditable multi-actor sessions cannot attribute clicks to Georg based solely on an arbitrary client field. All changes need server authorization.

## 5 · Recommended session check-in interaction (no invented acceptance)
1. Webchat: `@KFB Game Art Director Review <real-case-id>`; plugin skill resolves the actual source from GitHub and cached media. Do not pretend a generic ChatGPT `?q=` launch auto-loads plugin/images.
2. App surface embeds read-only actual evidence: **header with build and confidence + 3 urgent cards** and a compact `Show all` reveal. Display optional sources/compare controls only upon selection.
3. Georg chooses one card → model gets selected **text/structured evidence refs**; can discuss "compare option A and B" and annotate screenshot / VFX timing. On Web, image context transfer through `ui/update-model-context` is currently unsupported, so attach actual image via normal chat if ImageGen needs it. Do not silently rely on DOM screenshot.
4. ChatGPT produces a separately tracked image generation/paintover in the regular chat. Plugin registers bytes only if tested supported file resource/download path or explicit user-approved upload; otherwise status `GENERATED_NOT_PERSISTED`.
5. On `Approve design`, store a decision with exact `variant SHA` plus remaining risks. Show a **preflight/commit preview** with only approved items and precise Claude Code receiving owner.
6. On `Commit review packet`, GitHub app writes decision/manifest/critic notes and authorized media to the correct permissioned owner; verify actual branch head and read back all intended files before marking committed. Create the existing-issue/PR handoff; **do not directly patch game runtime**.
7. Claude Code source owner repairs; a fresh real game capture and independent critic follow. UI groups them under the same finding/thread and presents only measured changes and original approved Golden side by side.

## 6 · Minimum review packet per decision
`session_id, revision, run_id, finding_id(s), review_record_sha, exact repo/branch/head, device/camera/flags/event/frame pins, original media SHA, selected target(s) SHA and source `ACTUAL_GAME` vs `TARGET_GENERATED`, annotated region+timecode, critique, risk, ranked suggested seam/fix, decision actor+UTC+status, GitHub commit/PR/readback, actual tests+independent critic, rollback source, next gate.`
Attach no file that lacks permission+byte hash; item stays `EVIDENCE_PENDING` not incorrectly `COMMITTED`.

## 7 · Design/test gates for the first functional app view
**Bounded first sample:** existing source-backed Race Diorama screenshot (current #152) or real Aquarium clip only after #478 identifies actual module and path. A single 3-finding card list and one actual image pair, not a fabricated VFX video or generic design mockup. No new art style, generic placeholder images or replacement branding; reuse verified KFB visual donor as isolated real image before integration. Responsive compact web/mobile; buttons focusable; keyboard and touch; state survives reopening only through trusted backend.
**Static QA:** session data schema validates; count and filter statuses; selection updated in model context without false claim that pixels reached model; incompatible version guards; malformed/private media blocked; double-commit idempotent; approval cannot be inferred from assistant summary.
**Integrated QA:** actual file transfer in/out of native Webchat ImageGen and plugin; single `APPROVED` decision then real GitHub commit/readback; separate real Claude Code handoff remains unexecuted until named owner takes it; negative case missing image and revoked access.
**Human product gate:** Georg tests one actual session layout, selects an option and reviews its exact produced image. That is a meaningful creative decision, not another technical spec signoff.
**No published Site or Cloudflare Stage claim** until exact permitted URL opened, expected revision visibly present and Hub link verified. Neither is needed to develop a local/spec-only review system.
