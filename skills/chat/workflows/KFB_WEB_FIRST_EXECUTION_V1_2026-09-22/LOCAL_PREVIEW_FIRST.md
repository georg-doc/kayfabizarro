# KFB HTML Review First · browser/game/3D slices

Status: **CURRENT DEVELOPMENT REVIEW CONTRACT**
Purpose: fast visible iteration without Work, Cloudflare, repository clones, Python or Terminal.

## Rule

The default human review surface for Web/Claude browser/game/3D slices is a **zero-install HTML artifact generated in chat**.

Preferred artifact:

`<slice>_REVIEW.html`

It should open directly for Georg and show the exact candidate revision.

GitHub remains the source/checkpoint/archive.
Cloudflare remains a later milestone/publication surface.

## Preferred user loop

1. Web/Claude builds one bounded candidate.
2. Save the implementation checkpoint to GitHub.
3. Generate one self-contained or near-self-contained `REVIEW.html` from that exact head.
4. Return the HTML as a chat artifact.
5. Georg opens it and reports only visible/interaction issues.
6. Web/Claude repairs the same branch.
7. Generate a fresh review artifact.
8. Repeat until the slice is accepted enough for a milestone.
9. Only then consider Cloudflare/Hub publication.

No GitHub Desktop, repo clone, Python or local HTTP server is assumed.

## Artifact requirements

Prefer:

- JS/CSS bundled or inlined;
- Three.js/runtime code bundled into the artifact where practical;
- remote GLB/textures loaded only from immutable/pinned CORS-capable URLs;
- exact branch/head/revision visible in the UI;
- compact error/status diagnostics;
- only the assets needed for the current review.

The HTML artifact may be generated by chat and does not itself become the implementation SSOT.

The exact source remains on GitHub.

## When one HTML file is not enough

If browser security/CORS or large binary assets prevent a reliable single-file review:

1. first try a tiny generated review bundle with an `index.html` and only the required files;
2. keep it zero-install and downloadable from chat;
3. only if that still cannot work, use an existing local preview capability already present on Georg's machine;
4. do not make installing Python/Node/CLI a side quest;
5. Cloudflare is a last review fallback for a meaningful gate, not the debug-refresh loop.

## Browser evidence

Where useful expose:

- source SHA;
- loaded asset failures;
- console/runtime error count;
- current mode/state;
- key owner/source markers.

This is diagnostics, not generic UI chrome.

## Persistence

After each meaningful implementation checkpoint:

- commit to the named GitHub branch;
- fetch/read back the exact head;
- update Return/changelog only when the state materially changes.

Do **not** deploy after every checkpoint.

If a Web chat dies, the next chat reads the branch/Return and regenerates the review artifact from GitHub.

## Status language

HTML artifact:

`HTML REVIEW · NOT PUBLIC`

Cloudflare milestone:

`PUBLIC VERIFIED` only after the exact public route is opened and checked.

## Work escalation

A failed HTML review does not trigger Work.

Web/Claude fixes the source.

Use Work only when the next required action truly needs a capability unavailable to Web/Claude/HTML review.


## Reuse before new review chrome

Before generating a new browser/game/3D review artifact, read:

- `REVIEW_TEMPLATE_POOL.md`
- `review-templates/REGISTRY.json`

If a verified donor matches the focus, fork its accepted harness and change only the documented adaptation seam.

Current verified 3D donor:
`threejs-focus-review-v1`.

Do not redesign camera controls, panel grammar, toggle grammar or review chrome merely because the subject changed.
