# T1 · Lieferumfang und Abnahme

Ein vollständiger Slice, keine Sammlung unverbundener Minidemos. Dieser Auftrag liefert noch keine der unten geforderten Runtime-Prüfungen.

## Abgabe

| Lieferobjekt | Inhalt |
|---|---|
| ToolBox-Einstieg | drei funktionierende Tool-Links, Versionsstatus, Docs/LLM-Rückweg |
| Editierbare Quellen + Buildweg | ein benannter Authoring-Einstieg pro Tool; transitive Module/Assets, Source-Pins; keine nur handgepatchten Bundles |
| Veröffentlichte Vorschau | geprüfte tatsächliche URL, Source-Commit, Build-ID, Datei-Inventar; Originalexport erhalten |
| Config-Katalog | originale WIPs referenziert, Working/Approved getrennt, Quelle/Hash/Scope; verlustfreie Import-/Export-Belege |
| Actor-/Face-Abgabe | derselbe FB-Graft im Studio und Lab; Carl separat; Talk/Mod-Zustände dokumentiert |
| FONT_AUDIT | exakte Referenz/Family/Weight/Nutzung je Fund; ersetzt, optional oder fehlt; Fallback-Prüfung |
| MODULES-/Contract-Update | aus Originalcode bestätigte Pfade, APIs, Owner, Abhängigkeiten; keine Dokumentationsvermutung als Implementation |
| RETURN + Changelog + ZIP | tatsächliche Änderungen, Tests, Screenshots, offene Gates; vollständiges Dokumentations-/Source-Manifest, keine Font-Binaries/Secrets |

## Abnahmematrix

Jede Zeile im Return: PASS / FAIL / NOT_TESTED, Source/Build, Umgebung, konkrete Beobachtung und Evidenzpfad. Historische Donorbelege gesondert kennzeichnen.

| Gate | Test |
|---|---|
| Boot | alle drei Tools normal im Browser; richtiger Inhalt, kein Thumbnail-/Loading-Fallback als Erfolg |
| Erhalt | relevante Regler/Views/Exports mit Ausgangsstand vergleichen; keine still verlorenen Funktionen |
| FB | echte zusammengesetzte Graft-Figur, richtige Profilwerte, genau ein Kopf/Gesicht/Mund; kein roher Driver als Ersatz |
| Carl | Originalprofil korrekt gelesen/übersetzt, eigene Anker, keine doppelten Face-Parts |
| Motion | tatsächliche Clips aus mehreren verfügbaren Familien; mindestens Idle/Walk/Run plus vorhandene komplexere Bewegung; Head/Ohren folgen |
| Talk | an/aus während Idle UND Bewegung; Abbruch/Ende/Actorwechsel; sichtbarer Mund/definierter Rest; kein Lip-Sync-PASS daraus ableiten |
| Mods | jede angebotene Modoption an/aus/Reload, Rückkehr zur Basis; Demo-Nase nicht globaler Zwang |
| Roundtrip | unverändert sowie nach einer Änderung; unknown/false/0/null erhalten; andere Actors/global unverändert |
| Session | sauberer Browserzustand und bestehender Entwurf; keine Defaults über Georgs Änderungen; UI-Keys getrennt |
| UI / Fonts | drei Tools, sinnvolle Fenstergrößen und 200 % Zoom; keine Brandfonts in Controls; Fontnetzwerk blockiert → bedienbar |
| Pause / Ressourcen | Tabwechsel, Rückkehr, Toolwechsel, wiederholtes Öffnen; keine hängenden Eingaben, doppeltes Audio oder Mehrfach-Ticks |
| Publikation | exakte Build-Identität, bekannte Pflichtressourcen, URLs; HTTP 200 allein reicht nicht |
| Human | Georg beurteilt Lesbarkeit, FrizzleBob/Carl-Look, Regler und Toolwechsel; konkrete Rückmeldung dokumentieren |

## Release-Gate

ToolBox-Shell darf eine offene Lab-Funktion ehrlich als WIP/NOT_TESTED zeigen. Das ist dann eine nutzbare Vorschau, aber kein vollständig abgenommener Actor-Roundtrip-Slice. Ein fehlender finaler FB-Farbentscheid darf WIP-Nutzung nicht verhindern; er verhindert die Behauptung eines freigegebenen finalen Looks.

Normale Browser-/Integrationsbefunde werden nicht aus numerischen Proben oder einem Autoren-Housekeeping übernommen. Audio ausdrücklich nur als geprüft markieren, wenn tatsächlich gehört/geprüft.
