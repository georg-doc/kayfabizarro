## Notes

- A SYNC OF THIS PROJECT IS AN INVENTORY EVENT, NOT A REBUILD EVENT. Every screen loads geometry at a pinned commit, so upstream movement on `main` cannot alter a rendered screen. What a sync produces is: which packs became available, which recorded gap is now false, and which pin would have to move for a change to reach the screen. Never report "nothing changed" — report "nothing could have changed, and here is what is newly available".
- A PACK'S CONTENT IS COUNTED FROM ITS UNPACK RECEIPT OR A CONTENT SEARCH, never from a tree listing (the connector hides `.gltf`/`.bin`) and never from a truncated compare. `media/3D_Assets/KAYKIT_PACK_UNPACK_2026-09-18.json` is the pattern worth copying: ZIP blob SHA, file count, per-format counts, license flag, and an explicit byte-comparison against the other repo that holds the same pack.
- A QUATERNIUS CHARACTER IS NOT A KAYKIT CHARACTER, and the differences are the ones that cost time. No toe bones (so `facehost.v1`'s facing reader falls back to +z — measure with PoleTarget-vs-knee instead and state the magnitude). No `handslot` bones at all. The mech of the pair has NO ARM BONES. Clips are in place (`rootTravel` 0), so a stride must be measured from foot separation, not read off the root. And the runtime drops the dot in every joint name. Check all four before planning anything on a Quaternius pair.
- A DIRECTION READER MUST STATE ITS MAGNITUDE. Two readers that disagree are not a coin toss: on the Quaternius mech, PoleTarget-vs-knee gives 4.92 u and the foot-mesh centroid gives 0.0808 u = 2.3 % of figure height. Below roughly 5 % of the figure, a reader is noise and is rejected WITH its number. And do not pick the longest axis as "forward" — on anything with wings it is the span; decide by slice-profile asymmetry instead (mirror = span).
- A CONTINUITY GATE NEEDS A DECLARATION, NOT A TOLERANCE. Every state change a transition is supposed to make (altitude on a launch, moveState on a mode with different locomotion) is listed in the transition's `mutates`; everything else stays hard. A gate that flags a declared change as a failure is a gate that gets switched off, and then the real failures go unreported too.
- IN THIS PREVIEW THE WINDOW IS HIDDEN, and a hidden window freezes BOTH `requestAnimationFrame` AND `setInterval`. Any acceptance run that waits on the frame loop measures the browser. Drive the simulation from an explicit `advanceBy(seconds)` in fixed slices instead, and keep the frame loop for playing. Also: a `dt` clamp (`min(0.05, elapsed)`) is correct against the jump after a stall and wrong as a clock — catch up in slices instead of discarding the elapsed time.

- Model binaries (.glb/.gltf) do not appear in the CONNECTOR's github_get_tree listing (it filters to importable files), but the GitHub tree API returns them in full — that is how the Orc Brute and Monstrosity paths were proven in S24. Registry shards and the handoff JSON remain the richer source (they carry rig facts and dependency status); a tree walk proves existence only.
- `registry/assets/v1/packs/kaykit-mystery-series6.json` (916 assets) is too large for the connector copy; evaluate it over the raw URL when the rest of the cast is needed.

- Asset Registry stays the source of truth; this project is a read-only consumer.
- `_inbox/KayKit_PACKS_References_Scenes_Demos/*.gif` in georg-doc/KFB-Stunt-Car-Race is >5 MB and cannot be pulled through the connector; reference images come from the local `reference` folder / uploads instead. The two Patreon recap GIFs now in `ref/atlas/` came that way.
- The `*_Large` weapon/shield variants are the Rig_Large size class, not decorative alternates — verified as exactly 2× on six pairs and against three promos. Any new Large-tier resident equips the `*_Large` file; a Medium-pack prop on a Large rig needs `s: 2`.
- KayKit ships variants and accessories as SIBLING MESHES inside one file, not as separate files — `ActionFigure.glb` carries its own head, a cigar and a headband; each head file carries shell, face plane, cigar and headband. A variant swap is therefore a visibility question (`hide`), and a fitted part must switch off whatever the base already brings. Expect the same shape in any future KayKit pack with variants.
- Face expressions on the Action Figure are an atlas coordinate, not geometry: a 2×2 sheet of 512² tiles, one per expression, each head sampling one. Read the native tile from the mesh's UVs; clone material AND texture before offsetting.
- A prop's PIVOT tells you which hand it belongs to before any measurement: a pivot in the neck top of a guitar means the grip hand, not the strum hand. Getting that wrong cannot be fixed by tuning the aim vector — S26 spent a full roll sweep on a pose that was on the wrong arm.
- `KayKit_Mixed_Bag_1_FREE` IS fully usable (41 glTF files). Do not re-derive pack emptiness from `github_get_tree` — it hides `.gltf`/`.bin`. Use `github_search_code` for `Khronos glTF Blender` scoped to the pack prefix.
- The S18 identity rule is family-specific, not universal. Props whose LONG AXIS is local +Y (swords, axes, maces, staffs) attach on pure identity. FIREARMS carry it on local +Z (blaster, ToySoldier_Rifle, Marksman_Rifle) and always need `slotAxis {from:[0,0,1], to:[0,1,0]}` plus a computed roll — on identity the barrel points at slot-up, i.e. sideways in any standing pose. Check which axis is the long one before reaching for identity.
- A mapping is only proven when it holds across several clips: it is a fixed LOCAL rotation, so a pose-dependent winner is a pose accident. Verify any new `slotAxis` against at least three poses, and use `tools/prop-qa.html?identity=1` for the A/B against pure identity.
- KayKit ships colour variants in TWO shapes, and the file list does not tell you which: a second texture FILE (Cleric, Hero Man, Hoarder → `skin`) or a second PALETTE in the unused region of the same atlas (Marksman → `paletteShift`). Before concluding "no variant", measure the mesh UV ranges against the sheet size — a single texture file can hold two palettes. And the offset is per material: not every sheet of a pack has its second palette in the same place.
- Never take a SkinnedMesh vertex's world position from `applyBoneTransform` + `matrixWorld` if the node has been moved since binding — `bindMatrixInverse` is the bind-time world matrix, so the move is counted twice. Use `skinnedWorld()` from `lib/atlas.js`.
- `slotAxis.to` is NOT restricted to the six principal axes. It is any unit direction in slot space, so a 3×3×3 grid (26 directions) is the cheap honest search space — the six-axis version picked the least bad option twice and looked measured while doing it. And before optimising, fix the OBJECTIVE against the reference: read the held figure, not the loose asset render beside it.
- UI: the split-screen shell lives in `ref/ui-split-shell.html` with its build guide in `docs/UI_SPLIT_EINBAU_RESIDENT_ATLAS.md`. Header is one non-wrapping row whose middle scrolls and whose tail is fixed; panel overlays below 1100 px; three states (closed / open / view-only).
- A LEGACY FIGURE IS ASSEMBLED, NOT DRIVEN, and it needs TWO commit pins (figures @ the intake revision, rig @ `10a7fdce`). Zero bones, zero skins, Blender-primitive mesh names; four rigid part GROUPS go onto the rig's four bones. Never read "0 of N tracks bound" as incompatible, and never read "N/N bound" as compatible — the binding is against the rig. Part names are NOT a convention you can rely on: suffixes move behind the part name (`..._armLeft_broken`), the pack contains a typo (`ArnLeft`), and the torso may be named after the figure or a Blender template. Use the tolerant matcher in `legacyAssemble` and read its `warum` log; anything beyond the four parts (hats, visors, hoods, hair) must be re-parented explicitly or it vanishes.
- A HELD PROP IS HELD OUTSIDE THE FIST, not inside it. The handslot sits on the fist SURFACE (measured 0,119–0,205 from the centre across poses), so the resting push is `fist radius − slot offset + clearance` along the direction from fist centre THROUGH the slot — and that direction changes with the pose, because the wrist rotation carries it (her 0,14 on slot-Y, his 0,209; his changes again to −0,244 on Z once the elbow bends). A push toward the body centre is always wrong for a hand prop, however well "inside" was measured.
- A PENETRATION TEST NEEDS BOTH DIRECTIONS. Counting prop points inside the host misses a thin limb inside a large flat prop; counting host points inside the prop misses a thin prop inside a torso. Run both, and run them against the POSED skin (`applyBoneTransform` / `skinnedWorld()`), never the bind pose. `tools/phone-probe14.html` is the pattern.
- A PROP LENGTH IS CAPPED BY THE POSE, not chosen. Measure the FOREARM (chibi figures: 0,334, barely longer than the fist radius 0,32) and the hand's height as a share of figure height (27 % on a hanging arm). A prop longer than the forearm on a hanging arm hits the thigh, and no orientation fixes it — only a shorter prop or a bent elbow.
- Atlas-authored geometry lives in `lib/props.js` and is referenced by `gen:` with an `atlas://generated/` path. Keep that boundary visible: anything the atlas authors itself must still be measured like a loaded asset, and the split between measured size and decided proportions must be written down.
- KayKit promo renders detach parts in Blender. A prop visible "lying on the ground" or "held in hand" in a promo is very often a SIBLING MESH of the figure and therefore not placeable — check the mesh list before promising it (four cases so far: Marksman, Hoarder, Hiker, Protagonists).
