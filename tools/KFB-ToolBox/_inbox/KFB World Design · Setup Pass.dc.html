OPEN_DECISIONS

8 · GENUINELY UNRESOLVED

Settled owner and contract questions are not reopened here. Each item names what it blocks and the cheapest way to close it. OD-01 and OD-02 block G0.

OD-01 Is the Start Zone a sphere or a diorama? Blocks G0
Travel's world is a globe: globe-poc.js owns radius/seed/terrainType, bodenRadius(up) owns height, TinySkies ratios assume world radius 5. The KayKit editor reference and the Birthday staging both read as a local plateau/diorama. These are different spatial truths and the answer changes terrain silhouette, coast geometry, camera framing and every later placement number.
DECIDESGeorg + Travel owner (Astra) — not the design layer.
CHEAPESTOne sentence: “Start Zone is a bounded region on the existing globe surface” or “Start Zone is a local scene with its own ground, visited from Travel.” Everything else follows.
OD-02 Which renderer produces the G0 frame? Blocks G0
The execution brief requires the G0 still from “the real renderer and real asset pipeline”, no concept render. Two readable options: (a) the Travel v13 host itself — maximum fidelity, but Travel is mid-MVP1 and the design layer may not fork it; (b) a design-side three.js scene that loads the same assets via asset-repo.json at a pinned revision and mirrors Travel's light/sky parameters — honest about being a LookDev harness, cheap to iterate, and transferable as config. Without this answer, G0 evidence can be rejected on a technicality after the work is done.
DECIDESGeorg.
RECOMMEND(b) a pinned LookDev harness, declared as such in the REAL/PLACEHOLDER list, with every light/material/camera value exported as config so Astra can reproduce the frame inside Travel.
OD-03 Start Zone spatial layout Unresolved
Georg's world/setup drawing is the spatial reference and has not arrived. Until then every geography claim — where the coast runs, where Town sits relative to the clearing, where the approach path enters — stays provisional and visibly marked. Fable may still compose; it may not present invented geography as fixed.
CHEAPESTThe drawing, photographed (SLOT-02).
OD-04 Curtain: runtime path and module owner Unresolved
Two questions, one item. Path: is WebGPU compute cloth the primary with a deterministic fallback, or is the authored/skinned/spring version primary with cloth as an upgrade? The Travel baseline is WebGL 0.160 and the donor matrix warns against pulling WebGPU into it. Owner: does the reusable module live in Travel (a world/stage module beside the existing owners) or in ToolBox (authored asset exported to consumers)? Both answers must exist before G3.
RECOMMENDFallback-primary, cloth-as-upgrade, one owner with the state set as its public contract — so the visual bar is met on the baseline renderer without downgrading the target.
OD-05 Who owns clouds, rainbow and the lighthouse beam? Unresolved
Travel already owns sky, atmosphere, presets, day/night and the light budget. The three identity-bearing atmospheric elements are new objects that need a home: new Travel modules registered through lighting.register and the fx bus, or Stage-side authoring overlays that Travel consumes as config. Deciding late means either a second sky owner or a beautiful frame nobody can integrate.
OD-06 Cartoon Deformer: reuse the existing modules or build a Stage system? Unresolved
kfb-cartoon-deform.js and kfb-deform-instanced.js already exist and are shared across lines (S-03). Nobody has yet measured them against the P0 vocabulary (Bend / Skew / Taper / Squash / Twist, pivot + falloff, non-destructive stack, instanced variation). Until someone reads them, both “reuse it” and “write a new one” are guesses.
CHEAPESTRead two files (21 kB) and write a five-line capability verdict against the E11 deformer strip.
OD-07 Licence answer for any public export surface Unresolved · external
A public ToolBox that exports GLB/FBX/OBJ could turn licensed geometry into standalone redistribution. Needs written clarification before such a surface ships — and separately, the generative-AI input prohibition means asset content never goes into an AI tool. Not a blocker for world design; a blocker for export features and for any AI-assisted asset processing.
OD-08 Fixed asset revision instead of @main Unresolved
Open since the R0 re-home: asset references point at a moving branch and the baseline has no pinned asset revision. The casting return already worked around it by loading the shared library through a Registry pin. Any accepted G0/G1 frame is only reproducible if the asset revision is pinned in the returned config.
