## 1 · Product philosophy: chill first; optional challenge later
**Default is CHILL & FUN / PULL, DON'T GATE.** Free exploration, short optional harvesting/crafting, genuine Card discoveries, walking/boat/drive/flight, playful toy physics, music, resident interactions and relaxed construction. A Card never requires compulsory combat/survival grinding just to participate in KFB.
**Standard and Hard are future optional rule profiles over the exact same systems.** They must not create parallel savegames, bespoke enemy AI, duplicated Combat Arena math or different Card identities. One authored World/Item/Card truth; parameters/policies vary by active game profile. Difficulty is gameplay policy, not Story Mode D6, not Fluff High/Low polarity, not academic learner rank and not moral alignment.

### Rule-profile matrix (illustrative, NOT accepted numeric balance)
| Capability | Chill & Fun (default) | Standard (optional) | Hard (optional) |
|---|---|---|---|
| Hunger/attention/Fluff upkeep | off; no resource starvation | mild, optional consumption/replenish loop | one supply consumed after about 30 **active-play** minutes as a proposed future example; starvation consequence only after explicit balance |
| Gathering / Craft cost | common sources, tiny recipes, no cost on failed experimentation | moderate known recipes/sourcing | scarcity and meaningful crafting decisions, but not permanent deadlock |
| Equipment durability | presentation-only wear | mild repair loops | meaningful but reversible wear |
| Combat | forgiving encounters and recoverable respawn | normal danger & boss patterns | clearly telegraphed extreme boss attacks, possible one-hit moves |
| Death / loot | no punitive loss, return to safe anchor | small recoverable loss if accepted | harsher recoverable loss, optional special challenges |
| Navigation / learning | clear hints, unlimited practice | hints optional | optional restricted hints *within challenge*, but real Academy lessons remain accessible |
| Rewards | authentic Cards, origins, cosmetic/recipe discovery | same authentic Cards, challenge/provenance variation | same core Cards + additional nonexclusive challenge trophies/Afterglow markers |

**Important:** Time counts only while actually playing the active survival challenge; pause, menus, site/API waits, accessibility settings, offline, Maker/Academy lesson and authoring sessions must not drain survival supply. Do not quietly force a hard-mode timer during a long Blender session. Parameter tuning, save, switching and exploitation behavior require an explicit current-game-profile owner later. A named profile is only a policy set consumed by existing combat/inventory/world systems.

**Mode switching:** conceptual profiles `CHILL | STANDARD | HARD` are changeable only at defined safe boundaries (hub/safe anchor/session), with explicit preview of consequences. Hard-earned mode-specific badges may need mode-pinned challenge sessions; switching cannot duplicate resources, undo real acquisitions, or produce false Hardcore merit. Existing saved Cards/Lean Memories persist; the active challenge-profile receipt may be distinct from general story identity. A later ultra-hard/permadeath style would be a separate explicit challenge contract, never implied by ordinary Hard.

## 3 · One operation, three presentations, four authority scopes
Authoritative action and source asset always belong to one owner; multiple contexts project it differently:
1. **GOD MODE / AUTHOR:** privileged exact source asset and full permitted transform/module/WorldRecipe change, preview → validate → Stage candidate → human gate.
2. **PLAYER MAKER / CRAFTING:** same typed operation but restricted actor/item/anchor, Fluff cost and safe personal draft/cosmetic output; no arbitrary World edits.
3. **ACADEMY / FEYNMAN TUTOR:** same operation on safe clone/sandbox, with guidance/prediction/evidence and feedback (SEE → EXPLAIN → MODIFY → BUILD → SHOW → RECAP). Learning state E0–E5 independent from item/inventory/world truth.
4. **PLAY / COMBAT:** only a validated/equipped artifact is used by existing player/Combat owner; no weapons or VFX directly invoked from tutor or arbitrary upload.

**Not one giant app:** The World remains the World; God Mode uses the existing editor; Asset Librarian/FrankenStein/EyeRig/Material/Animation and FX tools retain their native formats; Academy controls educational adaptation and visual pedagogy, not geometry correctness or state. A Maker station is diegetic routing/UI for those owners. Reuse proof must be source-visible, not inferred from a URL.

### Bounded contract vocabulary (NOT live APIs or a new SSOT)
`SourceRef` (asset/license/version) → `AllowedCapability` (owner, action, permission) → `PreviewSandbox` (clone/draft + undo) → `Validate` (native owner checks) → `NativeConfig/WorldPatch` + immutable `MakerArtifactReceipt` → `ConsumerGrant` (Inventory/Player/Almanac/World after permission) → optional `LessonEvidenceReceipt`.
An actual `CraftRequest` uses the existing single Fluff wallet and recipe authority; only after validation+space does it commit resource debit+grant exactly once. Source-backed Card output always uses canonical `deckId + cardNumber` and existing PDF art; no invented duplicate Card, fake Deck or second Almanac.
`MakerArtifactReceipt` is a sidecar referencing existing specialist config/schema; no automatic second model registry. `LessonEvidenceReceipt` records observed learner manipulation, not something magically granted by spending Fluff. Craft items, game progression and verified competence are three independent truth domains.

## 4 · Example: Blaster customization → real Muzzle Flash workshop
**Source status:** entirely **POST-MVP illustrative sequence**. No source-approved Blaster, weapon socket, FX module, price or lesson is claimed from this document.

1. **Play/Acquire:** obtain a *real approved* existing KFB-compatible blaster/item variant through an encounter, Fluff recipe or Maker gift. A player can also take a sandbox clone in Academy without owning one.
2. **Inspect:** Asset Librarian presents exact source model, provenance/licence, GLB compatibility, rig/grip, host socket and baseline thumbnail; isolate the original source before changing anything.
3. **Craft/customize:** existing specialist material/attachment editor on a safe clone adjusts one approved part/color, then validates exact native config and saved variant (not a generic invented blaster builder).
4. **Learn VFX:** Academy's existing compatible RTT or tool view shows original muzzle-flash example, then player predicts a visible change, adjusts one bounded VFX parameter (size/spread/timing/color on actual source), sees before/after and explains the result. External shader/VFX examples stay isolated until source/renderer compatibility proof.
5. **Show/recapture:** the true before/after image/video and technical parameter/evidence receipt go to **Academy LearnerState** for recall; no fake skill certificate merely for paying Fluff.
6. **Package:** owner's source/license/mesh/rig/VFX validator accepts a versioned `item variant + effect preset`; resource payment grants a cosmetic/approved craft result to inventory only after actual packaging and save/readback. Item state remains an existing Bag/player item reference.
7. **Equip/try:** the Combat Arena/weapon owner alone approves whether a muzzle effect can be attached in a real fight. Cosmetic VFX alone does not grant damage, bullets, hitboxes or balance changes.
8. **Memory:** a small Maker/Journey Origin could reference “first personal blaster variant” (what/where/how) as an event; this must not create an extra canonical Card or pollute NPC/world/learner truth.

**Crucial anti-gate:** Players may **learn** the basic muzzle-flash technique without spending Fluff. Fluff may unlock an optional guided project, cosmetics, special materials or a maker-factory recipe, but should not be a prerequisite for competence. An optional alternate path can use demonstration of real skill to earn the recipe. Spending credits does not equal knowledge; learning evidence does not automatically mint rare items.

## 5 · User-uploaded 3D and “simulation inside simulation”
A future user can upload a **personal model**, but “upload” is not equivalent to “publicly install in World.” Use owner-backed trusted intake:
`USER FILE → PRIVATE QUARANTINE → identify format/rights/source → inspect/size/polygon/texture/animation/rig limits and privacy → safe isolated viewer → VALIDATE / request conversion → PRIVATE PREVIEW variant → explicit player/World owner apply → optional publish request`.
Prefer safe inspected GLB/glTF first; external FBX/Blender projects require offline conversion pipeline and source evidence. Never run uploaded JS/GLSL or scripts with privileged World/editor tokens. Enforce quotas/ACL/asset license checks and content rules at the server/tool boundary, not a hidden button. Do not expose another user's uploads in the public Asset Registry by default.

For custom personal islands/rooms: use Academy v0.8 **one canonical WorldRecipe** and a holographic miniature derived view, NOT a second nested fully running World simulation. One focused bounded instance uses the existing World owner; a private housing/retreat state is distinct from shared public World/Stage. Private/public sharing requires real authenticated backend, versioned manifests, approval, rollback and user-generated content moderation. A GPT Site alone cannot prove server-backed world tenancy or safe public community publishing.

Three permitted ways to make: (a) assemble existing source-backed approved modules, (b) modify native configs on a personal clone through current specialist tool, (c) import inspected personal GLB as private draft. At most **one** of these should be selected for each first proof. Avoid permission crossover between God Mode and Player Maker.

## 7 · Graveyard as playable memory, especially on Hard
The early Overworld concept contains death/Graveyard respawn; Resident Atlas has a **Graveyard dancing Skeletons** candidate. No existing accepted “sarcastic skeleton reacts to same boss death repeatedly” gameplay is proven.

Future event: `DeathReceipt{actorRef, worldRef, encounterRef/bossRef, profileRef, causeTag, deathOrdinalForEncounter, lastSafeAnchor, timestamp/session}` (illustrative contract).
Then **existing** Resident/ChatterBox uses the last few significant receipts to select a contextually different, authored short line/gesture/song beat. Example changes with repeats: first appearance is neutral observation; second recognizes the same boss; later responds to a new tactic or notes the player returned with different gear. Failure should be consequential but understandable, and recoverable through a known route.
