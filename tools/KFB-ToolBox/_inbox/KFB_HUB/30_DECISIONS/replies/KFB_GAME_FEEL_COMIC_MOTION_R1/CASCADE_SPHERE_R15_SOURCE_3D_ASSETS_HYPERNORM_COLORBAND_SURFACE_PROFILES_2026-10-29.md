## 1. Why it is attractive
- Keeps authored KayKit/Kenney source architecture (roofs, windows, trims, pipes, machines, bevels, contact, silhouettes) instead of forcing every city block to be a generic card cuboid. One environment might contain pure 16:9 HyperNorm Card Boxes, modified source buildings, and source-native protected props without an obvious style break.
- Reuse one KFB palette, clay surface roles, eye-catching hypernormalisation overlay and animated colorband family across **city, server farm, factory, fantasy block, Gutter maze and open-world pocket district**. A 3D asset changes *material identity*, not *physical/gameplay identity*, so 3D lighting, contact, shadows and nav/collision remain authoritative.
- Do not mistake "map the Hypernormalisation Engine" for directly turning a 2D animated canvas into an automatic six-direction world-space material on arbitrary meshes; that is a selective **texture/projector + zone masking** problem.

## 2. Verified original donor facts
1. **Actual WS1 `ws1/terrain-439:ws1/kfb-planet/src/look/terrain3.js`** exposes `applyTerrain3` and `applyShadowTone3`, 70s domain-warped 3D/world-position XZ flow bands, one host time, hMin/hMax and palette-based shadows. It hooks Three.js `onBeforeCompile` with `customProgramCacheKey`; fragment injection at `#include <color_fragment>` **overwrites full diffuseColor.rgb** by a flowBands lookup. Directly applying it unchanged to a multi-face vertical object will recolor windows/trim/full material and can give inappropriate XZ/height projection. WS1 `terrain3` is source-implemented on ground, NOT a tested source-building colorband adapter.
2. **Existing `tools/KFB-ToolBox/docs/CLAY_BUILDING_FACADE_ROUTER.md`** is CURRENT shared source/owner router. Prepared **S5 Building/Façade Clay Adapter** lives on non-main `georg-doc-patch-2`, protects actual KayKit/Kenney shape, measured foundations/connectors, door/window ROIs and coherent roof/body movement. New KFB material baseline K2 v10 clay/toolmix and independent CANON_3D/LIGHT_MODEL_R2. **Important: S5 is a prepared concept/source, not confirmed production adapter implemented in current private game.**
3. **R7 source GLTF material probe** `KAYKIT_PLATFORMER_R7_MATERIAL_ZONES_AND_TERRAIN_COLORBAND_WS0_2026-10-28.md`: actual original source often shares one `platformer_texture.png` atlas/material across all colored faces. `conveyor` has separate `threads` material, while button/lever/saw children are separate meshes using shared source atlas. For a single-material KayKit building or prop, a roof/door/windows-only effect needs **actual UV triangle/normal/geometry zone mask**, not a guessed node name or color filename. Original private Platformer EXTRA now exists at `georg-doc/KFB-Stunt-Car-Race@assets/kaykit-platformer-r1:kaykit_platformer_r1/` per R12.
4. **H13 HyperNorm 2D Canvas** (source `tools/KFB-ToolBox/_inbox/KFB Billboard Kaleidoscope H13/.../00_ONBOARDING.md`) runs an accepted audio/collage frame pipeline at 1024x512. Actual Clay Stage R2 `billboards/stage.js` maps H13/H14-derived canvas frames through `THREE.CanvasTexture` to a single 3D Billboard face. This is real source for **one textured surface**, not accepted automatic triplanar HyperNorm architecture on arbitrary GLTF geometry; current H15 API/renderer ownership still source-pending (R13/R14).
5. **Three.js material APIs:** `MeshStandardMaterial` preserves physically-based lighting/normal/roughness; `Material.onBeforeCompile` can modify built-in material shaders, requires stable `customProgramCacheKey` and explicit lifecycle, only under WebGLRenderer. `CanvasTexture` update uploads GPU texture on changed frame; avoid new texture per prop/frame. Documentation: https://threejs.org/docs/pages/MeshStandardMaterial.html , https://threejs.org/docs/pages/Material.html , https://threejs.org/docs/pages/CanvasTexture.html . Current target KFB host's pinned R3F/renderer version is the real implementation authority, not latest API generalized.

## 4. Projector / coordinates: the main design decision
- **Narrative imagery/cards/legible UI:** select one authored face or named source mesh, use existing valid UVs or a planar mapped *decal/overlay* with measured bounding box. Meaningful card illustrations, faces, glyphs and text will distort under full triplanar projection across a highly concave KayKit source. Use one or two readable hero areas. Physical roof slope and facade orientation require correct normals/local matrix.
- **Abstract motion / flow / psychedelic color fields:** source-shared `terrain3` sampler modified for **object-space or world-space tri-planar / normal-weighted projection**, with an actual material-zone mask. It can flow around building corners coherently in time and palette, but painterly flow cannot be assumed to carry semantic whole card pictures across seams. Face-specific UV atlas and physical clay corner/frame seams are often more intentional.
- **Source material preservation:** keep original mesh/GLTF hierarchy, pivot, PBR normals, maps, roughness, metallic, shadows and occlusion. Prefer mixing KFB palette/emission with source base material by a measured mask, not blanket replacing `diffuseColor.rgb` as `applyTerrain3` does. Glass/window, signage, graphic labels, face/eyes and interactable buttons should opt out or get controlled parameters (e.g. an illuminated window is not a live kaleidoscope by default).
- **Material adapter ownership:** may attach a renderer-specific *recipient-owned variant* to **cloned materials per mesh instance / optional shared uniforms** and use stable program cache keys; protect shared cached materials and textures in Asset Registry. Where source material is genuinely shared across several nodes, create author-owned node/UV/normal mask first; do not recolor all sibling assets. Dispose cloned materials/owned textures at host teardown; one scene rAF/one AudioContext.
- **Mask channels are separate:** `sourceMaterialZone`, `flowBandWeight`, `hyperNormWeight`, `gooInfection`, `shellDamage`, `cardReveal`, `3dgsVisibility`. Rendering reads accepted game state. Damage shader mask alone does not remove an occluding collider; 3DGS behind wall still requires correct depth/stencil ordering/alpha and an actual damage-sector collision opening.

## 5. Asset role profiles — avoid painting everything
**Hero building:** large broad facade may show source-authentic HyperNorm 2D animated image with muted colorbands on roof/wing walls. Windows/doors/frame remain original with KFB clay. Damage opening may reveal a source card or a separate **Gaussian Splat 3D pocket-world interior**, not per-particle physics.
**Regular neighborhood building:** source-native KayKit forms, softly palette-graded walls/roof; occasional abstract moving bands masked to a roof, marquee, chimney or door, not every house a TV.
**Factory / server / machine:** use real source 3D pipes, server racks, conveyors and mechanical assets, animated flow on physical conveyor/belt/vent and one controlled HyperNorm *display/control panel*, preserving source metal/plastic shading; black Goo as independent surface damage/infection.
**Streetlamp / sign / smaller prop:** global clay/palette/light with tiny selected emissive or ink patch; default no continuous live H13 CanvasTexture or new texture per object. A few hero artifacts can carry surreal projections.
