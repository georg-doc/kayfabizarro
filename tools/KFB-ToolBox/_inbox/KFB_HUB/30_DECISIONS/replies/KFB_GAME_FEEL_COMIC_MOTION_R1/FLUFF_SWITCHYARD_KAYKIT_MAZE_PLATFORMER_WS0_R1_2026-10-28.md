## 1. Creative thesis and moment-to-moment agency
A visible stream of small cartoon-eyed Fluff packets runs through a gridlike neighborhood and industrial switchyard. The player alters **real route topology** (switches, gates, validated placement sockets), sometimes removes contaminated building cells, then sees where the next packet wave really travels. Landmarks and restored civic buildings are outputs, not generic hitpoint bars. The best tactical moment is redirecting the same wave **without** shooting, although precisely damaging one infected shell is an alternate style once the Combat/WS1 gates pass.
One compact per-level **source → fork → obstacle → protected sink** grammar, with distinct player mobility vs packet flow. The same graph/state controls visuals, collision permissions and packet progress; sprites and InstancedMesh are presentation only. No unbounded city or spawning 1000 logical AI agents.

## 2. User roles and 3 levels (first vertical sequence)
### L1 SWITCHYARD · 90–150s target · teach route choice
- A small factory yard with one sender, one fork and one protected collection silo; one polluted short lane, one long safe diversion.
- The player can (a) flip one real floor lever to redirect the flow, OR (b) clear the polluted lane. Both must be logically sufficient, show different arrival paths. Visually show before/after via actual packet positions; objective is a defined threshold of delivered Fluff, not invented KFB score.
- Core input: approach lever / activate switch / optional select obstruction. Camera: legible isometric/tilted third-person; desktop/mech flight not required.
- First donor mix: Kenney Factory floor button, lever, conveyor T-junction/corner and KayKit City Builder road pieces, actual renderer source isolated before composition. Prototype Bits is stylistic reference until pack is confirmed installed.
- End: silo animates a tangible function and one local result receipt. No fake real Card or currency grant.

### L2 GOO JUNCTION · 150–210s target · platform height and reversible city intervention
- A 2-level small city block: one infected building shell blocks a short path, while a rooftop switch opens a longer service route. Both alternatives preserve connectivity for the *player's* physical access.
- Option A: reach roof via source-measured stairs/platforms, press a real 3D button to open a bypass; Option B: repair one snapped bridge/socket with existing (or explicit tutorial) Fluff state. Actual gameplay input/collision comes from receiving Player/World; component activation requires a true on-contact action.
- Black Goo should be a separate, localized material/state overlay on **identified infected KFB cells**, not spray a meaningless black texture over entire building or silently mutate its collider. The surrounding City Builder silhouette/roads stay recognisable; KFB-approved Clay shader warping is visual-only unless World collision also updates.
- Only selected adapted/buildable building cells may fracture/restore. Heritage/real OSM landmark cannot become a generic destructible prop.
- No full wave shooter dependence, no new reward system.

### L3 MECH RESCUE · 180–240s target · alternate defense plans
- One city/factory maze with two named sinks/landmarks, two route strategies and one elevated service switch. Enemy Goo wave can contaminate selected route cells. Flight/landing and precise source-backed Combat Mech attack are now *optional if verified*; no new movement, shooter or grapple owner.
- Strategy A: cleanse infected segment and restore a factory bridge. Strategy B: bypass via relay/switch and route a stream around the contaminated junction. Both must be provably capable of delivering valid packets to **both** sinks in a deterministic tiny graph, otherwise stage is unwinnable.
- Jetpack gives movement/reach advantages, but cannot bypass the packet-routing objective by simply flying over it. Grapple is FUTURE_SOURCE_REQUIRED (no verified runtime donor); no grappling in first proof.
- Optional one source-grounded Card/Almanac event after win only when existing owner supplies accepted CardRef and idempotent result receipt. Future OSM skin from **one bounded source-verified block**, not global city fetch.

## 3. Generation rules
**Best first route is MAZE, not OSM.** Reuse World Atlas Dungeon S13.2 semantics: cell graph and seam ownership (seamKey), deterministic rng(seed), measured 4-neighbor adjacency, validated empty/collision space, source-backed floor/wall/door classes, room/route reachability, recipe JSON export. Its existing grid unit **4** applies to the measured KayKit Dungeon pack ONLY and must not be assigned to Platformer/City/Factory without independent real source geometry measurement. Reuse algorithms/validators, NOT the Dungeon scene/module dimensions or second gameplay owner.
Reuse WhackMan wm-maze.js for graph BFS, gates and route planning; it is a donor of algorithms, not a second runtime Maze owner. A canonical cell/edge state with stable IDs and transactional ops must be selected by the WS1 receiver; per-source graph should be provable both **before and after** every gameplay action. Use one authoritative graph after moving a gate/switch and commit the action atomically with occupancy+save changes. Rendering and visual particles consume it; never use raycasts against texture/prop meshes as navigation truth.
Each generated seed has one visible sender, ≥1 fork, one reachable player action, one and later two sinks, at least **two distinct validated solution routes**, one actual consequence, and a valid reset. Generate candidate topology, then validate connectivity and action reachability; reject impossible seeds. Save scene recipe + small authored/seeded state; do not regenerate a saved run at a different seed.

## 4. State and agents
Proposed entity vocabulary, non-canon until receiving owner accepts:
- `Source`, `RouteNode`, `Switch`, `Gate`, `Socket`, `BuildableCell`, `Infection`, `Sink`, `Landmark`, `PlayerActionAnchor`, `PacketBatch`.
- Route state: directed edges with permissions from authored reversible switches/gates/cures; source and sinks have stable IDs. Global deterministic tick/wave scheduler belongs to one receiving World/activity clock.
- For each logical packet: source batch, type/class, current edge progress, outcome, unique receipt ID. Batch logic may aggregate groups of same route/destination so 100 visible spheres are **not 100 individual pathfinding queries**; instanced meshes or 2.5D billboards show eyes, squash/stretch, jumps, orientation and clear contact shadow. If a bunny swarm is selected, only real licensed/accepted bunny source art with source proof; it is not a placeholder requirement.
- No invisible particles counted as successes: visible arrival, failed/lost, reclaimed and corrupted receipt events must be unique and auditable.
- Visual crowd target for authoring can be **50–200 instances with ≤8 logical batches**, then profile on actual hardware (proposal, not a measured performance guarantee). Reuse one geometry/material as InstancedMesh, per-instance transforms, phase offsets, simple bounce; 2.5D sprite cards only where the source-backed pop-up atlas and ground shadow prove correct yaw and depth, especially mobile.
- Black Goo state `CLEAN → EXPOSED → INFECTED → CURED` is a **proposed mini-activity state**, not a global redefinition of V-531/532/533. q103 actual color cure rule still OPEN; for this proof use neutral player-triggered isolate/repair without claiming universal dye logic.
- `HEALTHY_BUILDING → INFECTED_BUILDING → DAMAGED_ADAPTATION → RESTORED` is reversible and visual output follows actual stable World object ID/repair record. No speculative conversion of authentic OSM building into a new destructible ownership class.
