# demo — NOTES (round 2, integration)

Game mode `/` (and `/?showcase=demo`): spawns the player in the best KayKit village, publishes landmarks + road routes
+ travel times, verification presets, a fading controls hint, real-input route scripts. **Default seed → 123**
(core request in CORE_REQUESTS.md; until applied, `/` is seed 1337 and spawns at 1337's best village).

## Files
| file | what |
|---|---|
| `choice.ts` | **boot-time** spawn choice (≤ a few ms): `?demoVillage` → FIXED[seed] → BEST[seed] → nearest village ≤ 10/18/28 cells → origin |
| `presets.ts` | GENERATED by `tools/presets.mjs` from the offline scan: FIXED (seed 123: full spawn constants), BEST (151 seeds → crossing cell) |
| `score.ts` | the spawn-village **scorer** (pure; any seed's WorldModel + a crown provider) — OFFLINE, never at boot |
| `graph.ts` | road BFS, open-ground walk Dijkstra to forest edges, polylines, `smoothPoints` (steering lines) |
| `plan.ts` | `planDemo(world, {at, cover})`: routes/landmarks of ONE village (`at`), or the full ranking (no `at`, offline) |
| `script.ts` | closed-loop real-input route scripts (`until` steps) |
| `scan.ts` | in-page seed scan (dynamic import only): fresh WorldModel per seed from the engine's layers, nature's `planChunk` for crowns |
| `tools/scan.mjs` | scan driver (one page per batch of 10 seeds, resumable JSON-lines) |
| `tools/presets.mjs` | bake scan → `presets.ts` |
| `tools/dump.mjs` | `__kfb.demo()` → `plan_<seed>.json` + `script_<seed>_<goal>_<gait>.json` |
| `tools/times.mjs` | leg seconds from shoot logs (`go:` marker → `arrive:` until) |
| `tools/regen.mjs` | ONE-COMMAND regeneration: (`--scan` full rescan) → BEST-only presets → dump plans → FIXED → copy route scripts |
| `tools/eval.mjs` | load a URL, evaluate an expression, print JSON (debug) |
| `hint.ts` | controls hint pill (unchanged) |
| `scripts/route_<seed>_<demo|bridge|forest>_run.json` | real-input route scripts for seeds 123 / 1337 / 42 / 7 (shoot with `--url "/?seed=<seed>"`) |

## Boot budget (integrator: demo ≤ ~1 s at boot)
`init`: `chooseSpawn` + `player.spawn` only. Seed 123 (FIXED): 0 world lookups, `initMs` 1. Table seeds: one
`villagesNear(seed, q, r, 1)` lookup. Unknown seeds: nearest proper village within 10 (18, 28) cells of the origin.
Routes / landmarks / travel are planned **lazily**: in `requestIdleCallback` after `ready`, or on first access
(`services.demo.landmarks|route|travel|plan`, `__kfb.demo()`, the `demo.*` presets). Only the chosen village is scored
(phases 1+2 on already-built chunks; nature's cached chunk plans give the crowns): 7.5 ms for seed 123.
`?demoScore=1` = offline mode: full ranking at boot (seconds; verification only). `__kfb.demo().boot` reports
`{choice, initMs, planMs}`.

## Scorer (score.ts) — 0..100, higher = better
- **village (35)**: buildings `10·min(1, n/18)·(0.5 + 0.5·onLevel/n)` + plaza 2 + well 1 + civic types (tavern, market,
  church, blacksmith) `min(1, k/3)` + core flatness `11·(cells ≤ 2 from the crossing at the crossing level, no ramp)/(land
  cells)` + cliffs `10·max(0, 1 − cliffEdges/8)` (cliff edge = adjacent core cells a walker cannot step between).
- **bridge (25)**: shortest road-graph path crossing → nearest bridge, polyline metres; full ≤ 110 m (A1 25 s at
  4.39 m/s), 0 at 170 m, 0 without a bridge within 12 road cells.
- **forest (20)**: walk Dijkstra (road or open ground, no cliffs/buildings/walls/fields/rivers) from the crossing to the
  first cell of a REAL forest (nature crowns: `inForest` ≥ 0.5 at the cell centre and ≥ 2 neighbours ≥ 0.35), end point
  moved onto the first crown − 1 m; nearest of the 6 cheapest edges by polyline metres; full ≤ 80 m (A1 18 s), 0 at 130.
- **route (10)**: forest beyond the bridge (search from the far bank, bridge banned behind): full if it adds ≤ 45 m to
  the bridge leg, 0 at +110 m — the gate route spawn → village → road → bridge → forest is one line.
- **view (10)**: from the village API spawn along its heading: buildings in a ±38° cone 5–55 m `6·min(1, n/5)`, well in
  ±35° 2, no ground > 1.5 m above the spawn within 25 m 2 (wall in the face).
- **dist (−3)**: `−3·min(1, d/600 m)`. Phase 1 (cheap, stages < 5) for every proper village within 40 cells (≈ 600 m);
  phase 2 (forest, route) for the best 3 within 30 points of the leader.

## Route scripts (script.ts) — closed loop
Goals: `demo` (spawn → centre → bridge → far bank → forest beyond), `bridge` / `forest` (spawn → centre, stop, then the
TIMED leg centre → landmark), gaits `run` (W) / `walk` (Shift+W). Each straight stretch is held `until` the player
passes the plane at its end (`__kfb.player().pos`); at a bend: keys up, `until` speed < 0.25, mouse drag
(`dx = −Δheading / 0.0042`), keys down. Stretches come from `Leg.smooth` (graph.ts `smoothPoints`: greedy shortcuts
inside the leg's own cells; on road/village cells within 2 m of the road polyline — houses overhang onto street grass;
a first all-cells version ran the knight into a house). Leg seconds = trace t(`arrive:` until met) − t(`go:` marker)
(`tools/times.mjs`), wall clock, includes the stop–turn–go at each bend. `__kfb.demo().scripts` has all five.

### Controls canon (W/S move · A/D turn · Q/E strafe · Shift sprint; character owns `player.yaw`)
- Route scripts (script.ts) steer with A/D only (no mouse): an initial on-the-spot alignment (A until aimed, any start
  yaw), then per stretch a closed-loop turn toward the stretch's end point — predictive release: the yaw rate is
  measured between `until` polls and the carry-over (≈ rate·0.06 s, measured 0.18 rad at 3 rad/s on seed 97) is
  subtracted — plus fine A/D taps and a re-aim every 15 m; W (jog, Running_A 2.49 m/s) or Shift+W (sprint, Running_B
  4.39 m/s) stays down through bends. Arrival: bridge = past the plane AND ≤ 3 m lateral (on the deck); forest = that OR
  within 4 m of the edge point. Steering shortcuts (graph.ts smoothPoints) may only cross cell edges a walker can step
  over with no wall, and pin the bridge approach to its axis.
- `__kfb.demo().scripts` = demo_run, bridge_run, forest_run (sprint), bridge_jog, forest_jog; `travel` adds `jog` /
  `sprint` (= the character's walk / run gait slots in canon). Controls hint text updated (hint.ts; hidden, never removed).

## Known issues / assumptions
- The spawn villages are 170–550 m from the origin (bridges are rare near the origin); streaming builds around the
  player, so this costs nothing.
- `presets.ts` must be regenerated (`tools/scan.mjs` + `tools/presets.mjs`) when terrain / roads / villages / nature
  change the world; a stale FIXED entry is detected lazily (console.warn when the planned village differs).
- Unknown seeds get the nearest proper village, not the scorer's best (scoring needs seconds; offline only).
- Walk = 0.955 m/s is the character module's clip speed; walking legs are 67–80 s (A1's "≤ 60 s for 90 m" fails there).
- Real-input times include 1–2 stop–turn–go bends (≈ 1.5–2 s each); a player steering while running is faster.
- Seed 42 spawn: the follow camera starts pitched steeply down / close (camera rig vs the building behind the spawn) —
  camera module behaviour, not fixed here; seeds 123 / 1337 / 7 start with a level street view.
