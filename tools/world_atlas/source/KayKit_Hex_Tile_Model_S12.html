Eine Kachel ist vollständig beschrieben durch die Klasse ihrer sechs Kanten. Alles andere folgt daraus: die Anschlussmaske ist die Bitmenge einer Klasse, eine Drehung ist eine Rotation des Strings, und „passt A an B“ heißt gleiche Klasse auf beiden Seiten der Fuge. Links das Kachel-Rendering von oben, rechts das gelesene Modell — dieselbe Quelle (lib/hex-grid.js · TILE_EDGES), damit Bild und Modell nicht auseinanderlaufen können.

Versuch 2 überlebten nur die spiegelsymmetrischen Kacheln — Masken, die unter d ↔ (6−d) invariant sind: A, D, G, H, I, K, L, M. Genau deshalb sahen gerade Straßen richtig aus, während jeder Knick spiegelverkehrt lag und jeder Strand landeinwärts zeigte. Versuch 3 misst hex_coast_B auf 88,7° (Kanten 1,2) statt 270°, und hex_coast_C auf 59,6° statt 300° — beides exakt die Spiegelung. Dasselbe Werkzeug prüft den Drehsinn getrennt: um rotDeg(1) = 300° gedreht wandert der Schwerpunkt von 88,7° auf 148,7°, also +60° = Kante i → i+1. Nach der Korrektur liefert der Pixelscan dieselben achtzehn Strings wie die Geometrie — zwei unabhängige Methoden, ein Ergebnis.

Fügeregel

Zwei Kacheln passen an einer Fuge, wenn beide dort dieselbe Klasse tragen: Sand an Sand, Wasser an Wasser, Wiese an Wiese. Das ist die einzige Regel, und sie ist prüfbar — auditTileFit vergleicht die gedrehte Maske der gesetzten Kachel Kante für Kante mit der Gegenkante des Nachbarn. Eine Zahl wie „22/22 gelöst“ prüft dagegen nur, ob eine Wunschmaske erfüllbar war, und blieb grün, während jede Kurve spiegelverkehrt lag.
