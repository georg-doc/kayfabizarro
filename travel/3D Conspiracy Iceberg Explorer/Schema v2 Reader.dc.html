Entry v2

Alle v1-Felder bleiben gültig. Jedes neue Feld ist optional — Bestandsdaten laufen ohne Migration weiter. Neu: summary, related, image, map.

  • summary — 3–4 Sätze, faktentragend: Namen, Daten, Widersprüche. Zwei Leseebenen (Mainstream: Kontext · Kenner: Easter Eggs). Quip bleibt FBs Spin danach.
  • related — max 3, Mix aus 1–2 existierenden IDs + oft 1 Ghost. Bewusst tier-übergreifend (Warburg: gute Nachbarschaft).
  • map — {region, x, y}, Koordinaten 0–1. Anwesenheit = Node im Map-View; tier = im Iceberg. Eins, das andere, oder beides.
Abweichung vom Sprint-Sketch ☞

Map-Platzierung sitzt im Entry (map: {…}) statt in einer separaten Node-Collection mit icebergId-Verlinkung. Ein Entry = eine Identität → Detail-Card, Bookmarks, FactChecks & Touren funktionieren automatisch in beiden Views. Map-only Nodes = Entries ohne tier.

Bilder & Redacted-Default

Redacted ist der Normalfall, kein Fehler. Gleicher Platzhalter für image: null, Ghost, Ladefehler, offline, CSP-Block.

  • Bild nur bei geprüftem Motiv + Lizenz + Attribution. Abstrakte Nodes bleiben redacted.
  • Referenz, nie Bytes (1000 × 20 KB = tot). Quelle: Wikimedia Commons Special:FilePath (offenes CORS, ?width=480).
  • credit + Quell-Link unter dem Thumb (CC-Pflicht, bei PD guter Stil).

Map-Modell

regions: [
  { id: "secret-space", label: "Secret Space Program",
    cx: 0.72, cy: 0.28, r: 0.11, wash: "mystic" }
]
links: [ ["mkultra", "stargate"], ["mkultra", "paperclip"] ]
  • wash referenziert die Palette (mystic/blood/…) statt roher Hexwerte → theme-fähig.
  • links = gezeichnete Verbindungslinien; related = semantische Nachbarschaft. Oft deckungsgleich, nicht zwingend.
  • Regionen werden im Map-View zu Sprungmarken (ersetzt die Tier-Rail).
